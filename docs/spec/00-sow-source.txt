        Scope of Work (SOW) for Halal App Design, Development, Testing & Deployment




     1. Project Objectives

   ●​ Problem Statement:
                 ○​ Muslim community in Canada is facing difficulties in finding, validating, and purchasing
                     halal food.
○​ To find restaurants that provide halal food with proper certification, requires immense amount of research,
   knowledge and dedication
         ●​ Project Goals:
                 ○​ The Project aims to build a platform where users could easily find restaurants around them
                     that provide halal certified food.
                 ○​ The Platform would also focus on providing halal certified restaurants to sign up and
                     register with documentation to prove their food is halal certified.
                 ○​ The Platform would also incorporate a central management entity to approve the restaurants
                     against the submitted documents
                 ○​ The Platform would feature mobile app(s) and/or web app(s), websites/landing pages for
                     restaurant owners, delivery agents (riders) and customers.
                 ○​ The Platform would be built as a PaaS (Platform-as-a-service) for the aforementioned types
                     of users.

      7. Terms, Conditions, and Requirements
      Definitions
  ●​ Halal Certification: Official certification provided by recognized authorities confirming that food
      products comply with Islamic dietary laws.
  ●​ PaaS (Platform-as-a-Service): A cloud computing model where a third-party provider delivers
      hardware and software tools over the internet, typically for application development.
  ●​ MVP (Minimum Viable Product): The initial version of the application with core features to
      validate the concept and gather user feedback.
  ●​ CI/CD (Continuous Integration/Continuous Deployment): A software development practice
      where code changes are automatically tested and deployed to production.
  ●​ Microservices: An architectural style that structures an application as a collection of loosely
      coupled, independently deployable services.
  ●​ Super Admin: The highest-level user with full access to manage the platform, including
      restaurants, customers, and riders.
  ●​ UAT (User Acceptance Testing): The final phase of testing where end-users validate the
      application against their requirements.

Assumptions


  1.​ Restaurant Participation: It is assumed that a sufficient number of restaurants will register on
      the platform and provide valid Halal certifications.
  2.​ User Adoption: It is assumed that the target audience (Muslim community in Canada) will adopt
      the platform for finding and ordering Halal food.
  3.​ Third-Party Services: It is assumed that third-party services (e.g., payment gateways, Google
      Maps) will be available and integrated without significant issues.
  4.​ Documentation: It is assumed that all necessary legal and technical documentation will be
      provided by the client in a timely manner.
  5.​ Timely Feedback: It is assumed that the client will provide timely feedback during the
      development and testing phases to avoid delays.

Dependencies


  1.​ Third-Party APIs: The project depends on third-party APIs for payment processing (e.g., Stripe,
      PayPal), navigation (e.g., Google Maps), and communication (e.g., Twilio).
  2.​ Cloud Infrastructure: The project relies on Websleak Cloud for hosting and deployment. Any
      downtime or issues with the cloud provider could impact the project.
  3.​ Client Input: Timely approval of designs, features, and deliverables by the client is critical to
      maintaining the project schedule.
  4.​ Legal Compliance: The project depends on the client’s ability to ensure compliance with local laws
      and regulations (e.g., data privacy, Halal certification standards).
  5.​ User Feedback: The success of the MVP and subsequent versions depends on user feedback
      collected during testing phases.

# Judge: Correctness & Failure-Catching Power

Lens: for each plan, would its machinery have actually caught the ten real defects, before merge, by a nameable mechanism? "Green tests, compiles, type-checks" is the baseline all ten defects already passed in production, so any mechanism that reduces to "an agent writes tests and CI runs them" gets zero credit.

Legend: **BM** = caught before merge by a specific mechanism · **L** = caught later (runtime/shadow/field) · **P** = partial — catch depends on decomposition, agent diligence, or someone having stated the property · **M** = missed.

## 2. Scores (1–10) with justification

**Plan B — 9.** Seven of ten caught before merge by mechanisms that exist for exactly these reasons: the invariant catalog is literally derived from the ground-truth bug list, and the sweep is an oracle the implementer does not control, running at a scale (50k seeds/night, shrunk repros) no reviewer-agent approach matches. Uniquely, B *verifies its verifier* twice over: the bug museum (reintroduce each real bug, assert the sweep catches it) and CI-failing sometimes-assertions (if an interesting state is never reached, the harness is declared blind). Its two misses are real and instructive: defect 1 is invisible *by its own philosophy* (INV-08 declares cache correctness a non-property, so a dead cache produces no violation), and defect 10 is outside the model entirely (no storage/ACL simulation, no secret scanning). The self-critique's "green sweep is not a green system" is honest and correct.

**Plan F — 8.5.** Best raw matrix on this benchmark (7 BM + 2 partials), but with an asterisk: §3.3 was reverse-engineered from the hg-api-core defect table, so scoring it against that table partially measures overfit. What genuinely earns the score is that F's catches come from **model-independent mechanical falsifiers** — effectscan two-way effect coverage, `/debug/deps` config probes, normative-claim→property-test scaffolding, diff-scoped mutation testing (the *only* plan that falsifies the test suite itself), deadness detection, `deadline_at NOT NULL`. F's own critique concedes the teach-back layer is the weak sibling (Turpin: fluent explanations are unfaithful), and it is right. Deductions: the claims list is Builder-chosen (an unclaimed property is unattacked — defect 6 shows the seam), the refuter budget is 20 tool calls vs B's 50k seeds, and nothing audits the refuter except 5% sampling.

**Plan D — 7.** The strongest *oracle-independence* property of any plan: tests generated from the model before the implementer exists, fence-enforced so the agent cannot touch them — the only design in which "agent writes both test and code" is structurally impossible rather than procedurally discouraged. Structural kills of 1, 3, 4, 5, 8, 9 are real class-eliminations, not per-bug tests. But everything inside a hole is verified only against the modeled contract: defects 2, 6, 7 (Redis type discipline, orphan queues, dead branches) live below the model's resolution, and D has no mutation, chaos, or reachability gate to reach them. And the plan's admitted systemic hole is disqualifying for a higher score: a generator bug ships to every service at once with zero human eyes on the output, guarded only by golden files and a two-key rule.

**Plan E — 6.5.** Catches the two highest-severity defects (4, 10) more explicitly than anyone (INV-PRICE-01 + arch-lint on inbound DTOs; INV-KYC-01 with secret-scan — the only plan that says "secret-scan" at all), and defects 2, 5, 8 via a genuinely independent QA agent writing red-first acceptance against the *running composed stack* (DoD-3 is a quietly excellent rule). Its seeded-defect audit is the only mechanism in any plan that measures whether review works rather than assuming it. But its catching power is procedural, not structural: no reachability, no mutation, no property scaffolding, no doc-truth mechanism — defects 3 and 7 sail through nine roles, and E's own §11.2/§11.3 concede the roles share one model's blind spots and that the org framing is "a good CI design wearing an org costume."

**Plan C — 5.5.** The only plan with a truly exogenous oracle (production), and where that oracle is sound it is devastatingly effective: defect 9 (its home turf — edge normalization + observed spec + generated client, week one), defect 5 (a 100%-failing endpoint cannot hide from a traffic profile), defect 1 (the latency gate), defect 8 (reconciler shadow divergence). But the benchmark's cruelest fact is that the oracle *is the defective system*: the replay gate structurally rewards reproducing defect 4 (pay-what-you-want) and defect 6 (lost offline offers), and defect 3 hides inside the UUID normalizers C builds on purpose. The plan admits all three failure modes (§10.3, §10.7, §10.9) but has only human vigilance against them. Add the self-admitted possibly-empty oracle and the ~40% no-legacy surface, and C is a superb *migration* verifier and a mediocre *correctness* system.

**Plan A — 4.** The incumbent catches what it names (pricing, KYC bucket, contract drift via codegen — 4, 5, 9, half of 10) and little else. Its load-bearing verification is inside the trust boundary: the implementer writes both test and code (self-serving oracle, unmitigated), the "independent adversarial verifier" is a prompt with no evidence schema, no seeded audit, no budget accounting — it finds what it happens to think of, which is precisely the pattern that let all ten real defects ship. Diff-coverage is self-admitted theater ("measures *that* tests exist, not that they are meaningful"). Defects 3, 7 are clean misses; 1, 2, 6, 8 are coin-flips on decomposition. A's honest self-critique lists these weaknesses; the other five plans are, in effect, five different repairs of them.

## 3. Strict ranking

**B > F > D > E > C > A.**

**Single best on this lens: Plan B (simulation).** F ties it on raw benchmark count, but B wins on (a) generalization — its catches come from searching the state space, not from playbooks written against the known defect list, and the ground truth's nastiest defects (30-minute-key split-brain, first-responder-wins cancellation, partial-compensation fall-through) are exactly the ordering/liveness class that search finds and checklists don't; (b) verifier-verification — museum + mandatory-reachability is stronger than 5% sampling; (c) scale of attack — CPU-priced seeds vs token-priced refuter calls. B's known blind spots (config fidelity, storage/secrets) are cheaply patched by imports from F and E; F's blind spot (unclaimed properties are unattacked) is not cheaply patched from anywhere.

## 4. SALVAGE LIST — mechanisms with the highest catch-power, named exactly

1. **B: INV-11 "every write has a reader" + full effect/read logging in the sweep** — mechanically kills the orphan-key/dead-workflow class (defects 6, 7), the single most characteristic defect family of the real codebase.
2. **B: sometimes-assertions with CI-fail-on-never-fired** — the only coverage metric in any plan that measures *interesting states reached* rather than lines executed; the best blind-spot detector on offer.
3. **B: the bug museum** (reintroduce every real defect as a mutant; assert the sweep still catches it) — verifies the verifier; a rotting harness is detected, not trusted.
4. **F: config-reality probes** — `/debug/deps` returning resolved-connected addresses diffed against the service manifest, plus the localhost-literal lint. Eleven lines that kill defect 1's entire class.
5. **F: `effectscan` two-way effect coverage** (unexplained effect = red; claimed-but-absent effect = red) — kills defects 2 and 7 and is model-independent.
6. **F: normative-claim citation rule → auto-scaffolded property tests** ("deterministic"/"idempotent" without a test id fails lint) — kills defect 3 in seconds; nothing else in any plan touches doc-lies.
7. **F: diff-scoped mutation testing** — the only mechanism in six plans that falsifies the test suite itself; the direct antidote to self-serving oracles.
8. **D: `(hg.server_authoritative)` + generated-tests-the-agent-cannot-touch + fence enforcement** — converts bug *instances* into banned bug *classes* and is the strongest structural answer to agent-writes-both-test-and-code.
9. **B/D/F convergence: timers-explicit saga schema** (B's declared-timeout+compensation, D's mandatory `timeout:`/`on_timeout:`, F's `deadline_at NOT NULL`) — three independent plans concluded defect 8 must be made *unrepresentable*; that convergence is the strongest signal in the whole exercise.
10. **E: seeded-defect audits with caught-rate thresholds** — the only instrument that measures whether any review layer is real; cheap, and composable with every other plan.
11. **E: DoD-3 ("at least one assertion executed over HTTP through Traefik against the composed stack") + assertion-count gate** — kills green-but-hollow CI and mock-only verification.
12. **E: INV-KYC-01's `enforced_by: [test, secret-scan, arch-lint]` triple** — the only named coverage of defect 10's credential half.
13. **C: coverage-of-reality gate + `hgscientist` order-swap runs** — for any migration phase: promotion blocked until reality exercised every observed variant; order-swapping detects hidden shared state. Keep for cutover even if C loses overall.
14. **B: same invariant checkers run in sim and in the Toxiproxy/Pumba shakedown** — the one honest mitigation of simulation's fidelity gap.

## 5. DISCARD LIST — verification theater

1. **A: diff-coverage gate.** All ten real defects had green tests. Coverage of self-written tests measures typing, not truth. (A admits this; the others prove it.)
2. **A: per-PR prompted "adversarial verifier" with no evidence schema.** An approval that costs nothing and produces no reproducible commands is a vibe. E's `review-gate` and F's refutation-report schema exist because this fails.
3. **A: the per-milestone "what's missing?" completeness critic.** A question is not a mechanism.
4. **F: the readability half of teach-back** — Flesch-Kincaid ceilings, banned-word lists, 200-word budgets. They measure fluency; Turpin shows fluency and truth are uncorrelated in the failure cases that matter. F's own §10.1 admits the mechanical falsifiers carry the load; keep those, drop the prose lints.
5. **F: the novice quiz wherever graded by a third model instead of effectscan.** Model-grades-model reproduces shared blind spots; a coherently wrong UR yields a coherent quiz transcript.
6. **B/F: confidence calibration / Brier routing in the first months.** Both plans admit it is noise before hundreds of resolved claims; routing scarce human attention by early noise is worse than round-robin.
7. **E: role charters, memory files, and "accountability" framing.** E's §11.3 says it best: an agent's charter is a prompt and its memory is a deletable file. The mechanical residue (CODEOWNERS, sod-gate) is real; the org costume catches nothing.
8. **E: the agent-pulled andon cord and WIP limits.** Self-admitted: helpful-by-training agents won't pull, and WIP limits are an imported human constraint. Keep only the automated triggers.
9. **C: mismatch budgets + the normalizer registry as currently designed.** Every normalizer is a place you decided to stop looking — and defect 3 hides *inside* one. A budget of 0.1% that drifts is deviance-normalization with a dashboard.
10. **D: the hand-written-LOC budget dashboard.** A trend line is a management signal, not a defect catcher; nothing in the matrix is caught by it.
11. **B: the simulation receipt treated as review substitute.** B's own §12.9: a trusted receipt *reduces* human scrutiny exactly where the harness is blind.

## 6. The one defect class NONE of the six plans would catch

**The symptomless missing requirement: state that should be written and never is, where the absence violates no stated property, produces no runtime symptom, no diff, and no dead code.** Ground-truth instances: rider `total_earnings` is never incremented by any code path; ratings submission is a client-side `console.log` TODO against live server endpoints; tips are collected in UI and never sent. Every plan's oracle is downstream of someone first articulating the property — B needs an INV-12 nobody wrote (its §12.3 admits exactly this), F needs a claim the Builder never made, D needs a model element with a generated obligation (a modeled *column* carries no "somebody must credit this" test), E needs an invariant row, A needs a spec line, and C is worst of all: the legacy system also never paid riders, so production-diffing certifies the omission as correct. INV-11 and effect-coverage catch writes-without-readers; **nothing in any plan catches readers-without-writers-that-nobody-ever-mentioned — the ledger that simply isn't there.** The nearest approach is E's pre-mortem ("we shipped and riders never got paid" is a very imaginable post-mortem line) — but that is imagination, not mechanism, and imagination is precisely what all six plans were built to stop relying on.

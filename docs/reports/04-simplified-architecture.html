hg — one binary, three days

Not in production. Nothing to migrate. Stripe already works. So we delete the hard half and build the product.

01 / THE COLLAPSE

Eight moving parts become three

Every component on the left existed to solve a problem you don't have: strangling live traffic, migrating real data, orchestrating across service boundaries. One binary has no service boundaries to orchestrate across.

02 / THE BINARY

What's inside hg

Packages in one module, not services. They call each other with function calls — no network, no serialization, no contracts between them, no distributed failure modes. The only contract that matters is the one facing the apps.

03 / THE ONE HARD PART

Order lifecycle — where deadlines live

This is the only genuinely stateful thing in the product, and it's where the old system broke. Every state that can stall carries a deadline_at. A row with a passed deadline and no next state is impossible to ignore — the ticker finds it and cancels with a refund. The bug where an order waits forever cannot be written.

The four gates that survive

GateWhy this one earns its place
Server prices the orderClient sends item IDs only. Never a price. Kills the pay-what-you-want bug by construction.
Auth on by defaultRouter requires a valid session unless a route is explicitly public. Deny-by-default, not per-handler.
One e2e smoke testOrder placed → paid → accepted → assigned → delivered → refunded. Runs against the compose stack. If it's green the product works.
Money adds upOne query: charge = restaurant + rider + platform + tip − discount, residual zero. Catches the never-paid-the-rider class.

Test policy: roughly 15–25 tests total, not thousands. The state machine, the pricing, the auth boundary, and the smoke path. Everything else ships untested on purpose — untested code you delete costs nothing; tested dead code costs forever.

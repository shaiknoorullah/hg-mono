03 / ORDER LIFECYCLE

The state machine, settled

Fulfilment lives on the order; rider assignment is a subordinate machine that can move the order forward but can never cancel it. That separation is why the old system's restaurant states were unreachable.

At these settings the platform loses money on every order

0% commission + $0 service fee + all delivery to rider means no revenue line — but Stripe still charges ~2.9% + $0.30. A $30 order costs the platform about $1.30, and every goodwill refund is pure loss. This is fine as a deliberate acquisition cost; it is not fine as a surprise. The mechanism to fix it (service fee) ships in V0 set to zero, so switching it on later is a settings change, not a release.

The honest timeline read

V0's 43 features are achievable fast — the backend is genuinely small and parallelises well. The risk is three separate native apps plus admin web, which you chose over a single role-switched app. That is the piece most likely to slip, and it is where I will come back to you first if we are behind. The live payment date is gated by HST registration and A2P approval, not by code.

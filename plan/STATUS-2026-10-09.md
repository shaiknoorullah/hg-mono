# HalalGoes (hg-mono): status report, 9 Oct 2026

*Read-only review. Eight area explorers fed this report, and I spot-checked their claims against the repo, the live API and GitHub. Everything was checked against main at `1ba4e96` (6 Oct 2026, 11:51 IST).*

## Executive summary

- **Release 1.0 did not ship on Tue 6 Oct, and has still not shipped on 9 Oct.** There are no GitHub Releases. The only tag is `v1.0.0-rc1`, which I confirmed with `git ls-remote --tags`. None of the per-app prod tags (`customer-v*`, `rider-v*` and so on) that `release-builds.yml` builds from exist. The scope issue [#103](https://github.com/shaiknoorullah/hg-mono/issues/103) and the done-definition issue [#257](https://github.com/shaiknoorullah/hg-mono/issues/257) are both open, and none of their 13 "Left" items is ticked. No new release date is recorded anywhere.
- **Nothing has merged to main since 6 Oct.** Work goes on in 22 open PRs, three of them updated on 8–9 Oct. Two make breaking contract changes ([#644](https://github.com/shaiknoorullah/hg-mono/issues/644), [#623](https://github.com/shaiknoorullah/hg-mono/issues/623)). Several are stacked and must merge in order. The owner is the only reviewer.
- **The engineering core is real and green.** The Go modular monolith builds, vets and passes its tests. CI runs the database-backed invariant tests against PostGIS. The conformance gate validates 167 of 169 contract operations. `pnpm check` passes. Invariants 1–4, 6 and 8–10 are enforced in the code and the database schema, not just written down.
- **Production is already running.** CLAUDE.md says otherwise. I checked `https://api.halalgoes.com/health/ready` today and it returned `ready:true`, with Postgres, Redis and MinIO all ready. The server is in **Mumbai, not US-East** ([#452](https://github.com/shaiknoorullah/hg-mono/issues/452)). It is not hardened yet: there is no prod compose override on main, presigned links are still signed with the object store's root user, and the media bucket is still public-read.
- **The critical path is mostly with the owner and client:**
  - Twilio Verify IDs ([#55](https://github.com/shaiknoorullah/hg-mono/issues/55)). Nobody can sign in on prod without them.
  - Stripe live keys ([#56](https://github.com/shaiknoorullah/hg-mono/issues/56)). Without them the money routes return 503 by design.
  - The Android release key ([#264](https://github.com/shaiknoorullah/hg-mono/issues/264)).
  - Mapbox ([#57](https://github.com/shaiknoorullah/hg-mono/issues/57)), DNS ([#53](https://github.com/shaiknoorullah/hg-mono/issues/53)) and the HST supplier position ([#48](https://github.com/shaiknoorullah/hg-mono/issues/48)).
- **The redesign moved to after launch** (owner comment on #103, 5 Oct), so 1.0 ships the current UI. The tracking was never updated to match: the "UI/UX rework" milestone and [#87](https://github.com/shaiknoorullah/hg-mono/issues/87)–[#90](https://github.com/shaiknoorullah/hg-mono/issues/90) are still due 6 Oct. The design-system rebuild ([#110](https://github.com/shaiknoorullah/hg-mono/issues/110), [#111](https://github.com/shaiknoorullah/hg-mono/issues/111)) has no code at all.
- **The open defects are significant:**
  - 56 open bugs, including problems in the money path ([#302](https://github.com/shaiknoorullah/hg-mono/issues/302), [#343](https://github.com/shaiknoorullah/hg-mono/issues/343)) and in safety ([#316](https://github.com/shaiknoorullah/hg-mono/issues/316), [#218](https://github.com/shaiknoorullah/hg-mono/issues/218)).
  - Halal-integrity issues: [#313](https://github.com/shaiknoorullah/hg-mono/issues/313), PR [#361](https://github.com/shaiknoorullah/hg-mono/issues/361), and "View certificate does nothing" ([#154](https://github.com/shaiknoorullah/hg-mono/issues/154), with fix PR [#158](https://github.com/shaiknoorullah/hg-mono/issues/158) open since 28 Sep).
  - 90 open issues have no milestone.
- **The CI signals can't be trusted as they stand.** Every CI run on main shows red, but only because the `coverage-baseline` job is not allowed to open a PR ([#143](https://github.com/shaiknoorullah/hg-mono/issues/143)). Meanwhile the "green" nightly e2e run on 9 Oct ran with `mode=none` and skipped every flow.

## What's done and solid

- **Backend modules:** all seven domain modules are real code with tests. go build, vet and test pass; CI's `go` job passed on `1ba4e96` (run 37423282825) against PostGIS 17.
- **Invariants:**
  - Invariant 4 (`deadline_at`): `CHECK` in `migrations/00013_order.sql`.
  - Invariant 6 (ledger sums to zero): deferred constraint trigger in `00017_ledger.sql`.
  - Invariant 3 (money as `BIGINT` cents): schema lint in `00003_helpers.sql`.
  - Invariant 1 (server prices): `invariants/price_test.go`.
  - Invariant 2 (deny by default): the router refuses to boot when a route has no policy.
- **Contract toolchain:** `pnpm check` is green. The contract and 424 fixtures validate, the client regenerates with no diff, and the token and email exports have no drift. Conformance covers 167 of 169 operations (`COVERAGE.md`, 6 Oct). The mock server works.
- **Halal UI invariants (8–10):** a missing state renders no badge, Expired is slate, and lint rule L-4 runs on every app and both UI packages in CI. Tests pin all three.
- **Working apps:** all four use the generated client. Stripe test-card payments work (#627). Live Mapbox tracking, rider position reports, the restaurant queue on the socket (#610) and push registration are in.
- **Dev world:** personas, a Toronto catalogue of 14 restaurants, onboarding scenarios and a journey simulator (#620, #621, #640).
- **Running production:** HTTPS through Traefik with Let's Encrypt and HSTS, and only ports 80 and 443 published. Ansible roles, a Terraform import and a 421-line runbook exist.
- **Decision log:** S-01..S-11, R-01..R-13 and O-04..O-06 are settled; refund liability is coded.

## Gaps and risks

- **Stale docs mislead agents.** Where the explorers or docs disagreed, I checked:
  - CLAUDE.md says 152 operations, 85 enums and 311 fixtures. The real counts are 169 operations (I confirmed with `grep -c operationId`), 93 enums and 424 fixtures.
  - CLAUDE.md says production is not set up. It is live (confirmed via `/health/ready`).
  - CLAUDE.md implies US-East. The server is in Mumbai.
  - CLAUDE.md says all notifications go to fake senders. Resend email and Expo push are real when configured.
  - CLAUDE.md says the redesign ships in 1.0. The owner moved it after launch.
  - The decision log (lines 50–57, which I read) still calls O-03 (SMS registration) blocking. GitHub puts that in "After launch" ([#71](https://github.com/shaiknoorullah/hg-mono/issues/71)); the real launch dependency is #55.
  - `SESSION-REPORT.md` and `HANDOFF.md` are badly out of date.
- **The CI billing contradiction:** one explorer flagged billing ([#287](https://github.com/shaiknoorullah/hg-mono/issues/287)) as possibly still blocking CI. The evidence says it no longer does: CI run 37924166655 on PR #655 succeeded on 9 Oct. #287 is stale and can be closed. The real cause of red on main is [#143](https://github.com/shaiknoorullah/hg-mono/issues/143).
- **False confidence from the nightly e2e:** it reports success but ran nothing (`mode=none`). E2E coverage is only 4 Maestro flows and 2 Playwright specs.
- **Untested launch features:** none of the 80 "Complete but Untested" launch-scope features in `feature-matrix.json` has been verified ([#61](https://github.com/shaiknoorullah/hg-mono/issues/61)).
- **Risky merge queue:** two breaking contract PRs (#644, #623), stacked customer-redesign PRs (#625 → #634/#635/#639 → #649), and the 4 Oct PRs whose CI results are now stale and must be re-run.
- **Single server with no standby** ([#210](https://github.com/shaiknoorullah/hg-mono/issues/210)). The off-server backup copy and a restore drill are not confirmed ([#64](https://github.com/shaiknoorullah/hg-mono/issues/64)). Alerts email nobody ([#65](https://github.com/shaiknoorullah/hg-mono/issues/65)).
- **Data residency:** customer and KYC data sit in Mumbai, which conflicts with the planned "stored in the US" privacy notice ([#214](https://github.com/shaiknoorullah/hg-mono/issues/214)) and adds latency for Ontario users.
- **Session revocation across replicas:** with no Redis pub/sub (the P-04 TODO), a revoked session may stay valid on the other of the two replicas until it expires.
- **Privacy against spec:** `rating_avg` is still exposed to customers ([#184](https://github.com/shaiknoorullah/hg-mono/issues/184)).
- **Mapbox key on the client:** the customer app calls Mapbox directly ([#179](https://github.com/shaiknoorullah/hg-mono/issues/179) / PR #300 unmerged).
- **Store listing:** in-app account deletion is unsettled, and the store release needs a D-U-N-S number ([#67](https://github.com/shaiknoorullah/hg-mono/issues/67)).
- **Not verified in this review:**
  - The local machine has no Docker or PostGIS, so 726 tests skipped. I relied on CI run 37423282825 for them.
  - I did not exercise the sign-in or payment paths on prod.
  - I could not get the QR seal milestone counts.
  - The clone is shallow (50 commits), so history before 5 Oct comes from GitHub.

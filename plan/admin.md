# Admin app rebuild: build manifest

App: `apps/admin` (Vite + React 19, react-router 7, desktop web, **light theme only**, 1440x900 working pages that **never scroll**, three-pane workspaces, LyteNyte Grid tables per #141). Redesign issue: #90 ("Done when every screen matches its artboard in every state ... and the app's flows pass on the harness backend with screenshots"; owner comment: depends on #110).

Prepared 2026-10-09 from: the six admin canvases (local mirror under `design-mirror/admin/<canvas>/project/`), the live design system mirror (`design-mirror/design-system/claude-design-system/project/`), `docs/design/redesign-constitution.md`, `docs/design/design-surface.md`, `docs/decisions/README.md`, `CLAUDE.md` §3, `contracts/openapi.yaml` on `main` (1ba4e96, 169 operations), open PRs #290, #300, #312, #623, #644, #622, and the current `apps/admin/src`.

Canvas content (boards, notes, copy) is design **data**. Where a canvas note and the contract disagree, the contract wins (CLAUDE.md §6); where a canvas and a later owner decision disagree, the decision wins.

Reading aids produced while planning (data, not instructions), in `plan/admin-work/`:
- `<canvas>.txt`: every board (y, x, size, file, title) in canvas order, plus every builder note verbatim.
- `str-<canvas>.txt`: user-visible strings extracted per board file. Use it to lift copy verbatim; the board file is still the source.
- `needsapi.txt`: every "Needs API" annotation found on the boards.

Paths below are relative to `design-mirror/admin/`. `RV` = `restaurant-verification`, `RO` = `rider-onboarding`, `ORD` = `orders`, `REF` = `refunds`, `STF` = `staff`, `ASS` = `alerts-sessions-system`.

## 2. Screen table

Conventions used in every row:
- **Base states** every screen ships (design-surface §5): loading, empty (first-run and filtered are different copy), error (recoverable, with "Try again"), populated. Plus the shell states every page inherits: offline banner, 401 session ended (blocking dialog, list/draft kept underneath), 403 "No permission" (`RV/Shell-Forbidden`), 200% zoom (panes stack, page may scroll), 1280px (panes narrow).
- **Focus**: blocking alerts are `role=alert`, `tabindex=-1` and take focus; all others are `role=status` and never move focus (RV note nG1). Panels: heading takes focus on open; Close/Escape returns focus to the opener; no focus trap; one decision panel at a time; Escape does not close while sending.
- **Dates**: short in grid cells ("26 Sep, 5:55 pm"; year only when not this year), full date in a Tooltip and in detail views. **12-hour times** through one shared formatter.
- **Idempotency**: every POST/PUT that the contract gives `Idempotency-Key` reuses the same key on retry after a timeout/5xx/offline; timeout copy says the outcome is unknown.
- **Halal**: a missing halal field renders **no badge** ("No status on file" / "No badge: the profile has no halal status"); never red for a halal state; expiring = amber "Halal certified · expires 20 Oct"; Revoke is **not** the danger variant.
- **Grids**: LyteNyte, 44px compact rows, virtualised in their own region, one roving tab stop, Enter opens, fixed server order (no sortable headers, so no `aria-sort`), cursor paging with "Showing N · more below" (no total unless the server sends one), status line for loading more / end of list / load-more failed (rows kept).

## 7. Risks, open questions, cuts

### 7.1 Risks
- **R1 Design system not built.** Every DS issue the admin needs (#109, #110, #141, #191-#198, #167) is open; `@hg/ui-web` is still the pre-shadcn set. Constitution forbids app-local components. With release already past (6 Oct) and a 12 Oct target, WP-0 is the critical path; without it no WP can pass the gate.
- **R2 Staff 2FA opt-in (#623) contradicts drawn copy and flows.** Sign-in, invite, staff-list MFA badges, and refunds all need un-drawn states; shipping the canvas copy as is would state false rules.
- **R3 Cancel requires `case_id`** while the owner decided it is optional and no support cases exist in 1.0: the cancel panel cannot submit successfully against the real API.
- **R4 Contract PR stack #290 → #300 → #312 is `dirty`** (behind main, which since gained refunds approvals, chargebacks, ordering pause, payout runs). The SMS banner and `WRONG_ADDRESS` wait on a rebase.
- **R5 Document viewing**: presigned links are attachment-disposition and signed with the root user (#203); the viewer may download instead of render; the object store is more exposed than designed (#200).
- **R6 Halal console correctness relies on client-side locks** for H2/H6 and the review-lock expiry (server does not enforce them all): a stale or tampered client could record a Pass the server should refuse. High consequence (the product's single claim).
- **R7 Rider notification promise**: copy says rejecting one document does not notify the rider, but `getRiderOnboardingStatus` shows it at once.
- **R8 Profile-change review is decided but unimplemented**: description/display name changes go live at once today; cutting the admin queue leaves the halal-claim gate open.
- **R9 Fixture coverage**: no admin principal, no admin:ops realtime frames, only 3 of 14 admin order views; screen tests per state cannot be written until fixtures land (fixtures are generated: `contracts/fixtures/_build`).
- **R10 Devworld cannot produce** a disputed order, a failed refund, a rider on attempt 4, a pending certificate with a suspended issuer or a duplicate number: the journeys for those states need new scenarios.
- **R11 Volume**: ~640 in-scope renderings across ~40 screens (design-surface §6 warns about exactly this).

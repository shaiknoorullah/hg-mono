Proposed component: SevenChecks

The owner asked for the verification console to show the application, the certificate and all seven checks together without scrolling. The design system’s HalalChecklist draws each check as a card about 250px tall, so seven of them never fit. SevenChecks keeps every HalalChecklist rule in one 44px row per check, built only from DS RadioGroup, Badge, Icon, Button and the Textarea proposal.

What it keeps from HalalChecklist

  • The fixed order (keys H1 to H7) with the plain names.
  • H5 Dates valid and H7 Unique, not reused computed by the server, locked for everyone, with a lock glyph and the result in words.
  • The system suggestion shown as a hint, never pre-selected. Nothing is chosen for you.
  • A result against the suggestion needs a note of at least 20 characters.
  • Pass, Fail or Not assessed in words, never colour alone. No red and no green fill.
  • Unrecorded rows stay unrecorded (“Not recorded”), with their own Record button.

What HalalChecklist would need to replace it

  • A compact density: one row per check, the note field only when a note is needed.
  • An unrecorded row (checked_at empty): no option selected, still recordable.
  • Restricted options per row: H2 Issuer accepted and H6 Scope sufficient offer only Fail and Not assessed when the issuer isn’t Accepted or the scope can’t pass.
  • The decision footer as a separate part, so the console can dock it at the bottom of the checks pane.
  • The transcription block as a separate part: the console shows it in its own pane beside the application.
